# 김도현

_updated at 2026-06-01_

더 좋은 제품이 더 많은 사용자를 만든다고 믿는 프론트엔드 엔지니어입니다.

기능을 구현하는 것보다 "더 나은 UX가 있는가"를 먼저 고민합니다. 스프린트마다 기획자, 디자이너와 UX를 논의하고, 더 나은 방향이 있으면 가감없이 의견을 전합니다. 
이 과정에서 개발자 관점의 UX 피드백이 팀의 자산이 된다고 믿습니다.

코드도 같은 기준으로 봅니다. 읽기 좋은 코드인지, 각 함수의 역할이 뚜렷한지, 하나의 모듈이 두 개 이상의 도메인을 담당하진 않는지를 매번 검토합니다. 

디자인 시스템 구축과 API 자동화 같은 플랫폼 작업도 결국 팀 전체가 더 빠르게, 더 좋은 제품을 만들 수 있도록 하는 수단이라는 생각으로 해왔습니다.

#### 신규 B2B 플랫폼의 프론트엔드 구조와 핵심 기능을 구축하였습니다.

- Next.js App Router 기반 **Server/Client Component 공통 아키텍처**를 설계
  - 프로젝트 초기 Server/Client 간 분리가 페이지별 담당자마다 구조가 불일치한 문제가 발생
  - Server/Client 간 page·container·components 아키텍처 설계로 데이터 조회와 UI 렌더링 흐름을 표준화
  - 모든 API 호출은 **Server Action**으로 수행하여 클라이언트 내 API 엔드포인트 노출 차단
- Kakao Map 기반 차량 관제 시스템 렌더링 성능 개선
  - 수천 대 차량 마커를 동시에 표시하면서 DOM Element 증가로 지도 줌/이동 시 프레임 드랍 발생
  - 지도 줌 레벨과 viewport 기준 **클러스터링**을 적용해 렌더링 대상 수를 제어하여 지도 이동 성능을 **60fps 수준으로 유지**
- WebView/Native Bridge 통신 안정성을 개선
  - Native 응답 손실로 인해 WebView 상태 불일치 및 응답 대기 화면 멈춤 문제 발생
  - useEffect 기반 전역 함수 등록/해제 구조를 `useSyncExternalStore` 기반 모듈 레벨 구독 구조로 변경해 Native 응답 상태 관리 일관성 개선
- Next.js App Router 기반 통합 로깅 환경 구축
  - Edge Runtime, Server, Client 등 실행 환경별 로그 수집 방식 차이로 로깅 코드가 도메인 로직에 분산될 우려 발생
  - Server Action 기반 **공통 logger**를 구현해 호출 위치와 관계없이 **AWS CloudWatch Logs Insights**에서 로그를 조회할 수 있는 구조 구축
  - Client Runtime Error, API 호출 성공/실패, Server Error를 각각 error 이벤트, SDK lifecycle, instrumentation.ts에서 수집하도록 표준화
- B2B 파트너 온보딩을 위한 개발자센터를 구축
  - 백엔드 파트에서 고객사에게 API 명세를 안내하기 위한 문서형 웹앱 요구사항 발생
  - 백엔드 파트가 OpenAPI 3.0 기반 YAML 문서를 작성하면, 이를 파싱해 웹 페이지로 보여주는 구조 구현
  - https://developers.carplat.co.kr

  - 시맨틱 디자인 토큰 기반의 **라이트/다크 테마 구조**를 설계하고, data-theme 속성만으로 하위 UI에 테마 토큰이 적용되는 다크모드 시스템 구현
