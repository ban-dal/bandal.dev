# 김도현

_updated at 2026-09_

4년간 B2B 제품과 사내 운영 도구를 개발해 온 프론트엔드 엔지니어입니다.

신규 모빌리티 플랫폼의 프론트엔드 공통 구조를 설계하고 앱 내 WebView 개발을 전담했으며, 7개 서비스에서 사용하는 공용 UI 컴포넌트와 API 타입 자동화를 구축했습니다.

운영 데이터 분석을 위한 Text-to-SQL 챗봇 구축 및 Electron 기반 Native Bridge 구현 등 프론트엔드 밖의 문제도 해결해 왔습니다.

#### B2B 모빌리티 플랫폼 신규 구축 및 확장

**2024년 10월 ~ 2025년 05월 구축·출시 / 이후 유지보수 및 기능 확장**

- FE 개발자 4인으로 B2B Web·Admin·WebView를 신규 구축해 2025년 05월 출시했습니다.
  - 폴더 구조, query·mutation 처리 흐름, 로딩·에러 fallback 등 프론트엔드 공통 구조 설계
  - 회원 가입, 로그인 및 토큰 관리, 권한 처리 구현
  - 앱 내 WebView의 프론트엔드 개발 전반 전담, Web·Admin은 일부 페이지 담당
- 차량 관제 지도에서 수천 대 마커가 몰려도 조작 가능한 성능을 확보했습니다.
  - Chrome DevTools FPS Meter와 4x throttling 환경에서 지도 이동 시 15fps 이하 프레임 드롭과 프리징 재현, 기획자와 필요한 마커 밀도 협의
  - 클러스터링, 이동 중 마커 렌더 debounce, 이미지 기반 마커를 조합해 고밀도 지역에서도 **15fps 이하 → 60fps 유지**
- 모바일 WebView 환경에서 BLE 차량 제어, 카메라, GPS 등 Native API를 활용한 기능을 구현했습니다.
- Next.js 앱의 로그를 구조화된 JSON으로 표준화해, 에러를 즉시 인지하고 바로 추적할 수 있는 흐름을 구축했습니다.
  - Client Runtime Error, API 호출 lifecycle, Server Error를 각 Runtime의 진입점에서 수집해 Server Action 기반 logger로 전송
  - 대응이 필요한 에러는 Slack 알림으로 즉시 인지
  - AWS Logs Insights에 저장 쿼리를 구성해 같은 페이지에서 발생한 에러, 특정 사용자가 이용 중 겪은 에러 등을 바로 조회
  - [Next.js에서 자동화된 로깅 구조 만들기](/blog/nextjs-logging-strategy)
- 개발 인력이 없는 렌트카 업체도 백엔드 파트의 OpenAPI를 연동할 수 있도록 [개발자센터](https://developers.carplat.co.kr)를 구축했습니다.
  - 비개발 직군도 이해할 수 있어야 한다는 요구사항에 맞춰 OpenAPI YAML을 파싱해 API 명세 표시
  - 차량·상품·예약·스케줄 등 API 사용에 필요한 도메인 가이드를 Next.js MDX로 작성

  - endpoint·method별 request·response 타입을 자동 생성해 적용 이후 API 스펙 오용으로 인한 오류 **0건**
  - 생성된 타입을 기반으로 AI가 API 연동 코드와 Storybook용 mock object까지 생성하도록 활용
- 자체 DatePicker 및 Table·ColorPicker·Markdown 입력을 지원하는 Rich Text Editor 컴포넌트를 구현했습니다.
  - Rich Text Editor HTML 결과를 업로드 전 gzip 압축해 전송·저장 크기 평균 **70~80% 감소**
  - 검색 요구사항이 없고 업데이트 안내 위주로 쓰이는 B2B 서비스 특성을 기획과 확인한 뒤 압축 저장 적용
